# v.2.1.0
Versión menor y no parche: corrige vulnerabilidades sin cambiar la API pública, pero hereda el cambio de comportamiento de Kitpymes.Core.Logger 2.1.0 (abajo).
Corrección de seguridad: Kitpymes.Core.Logger 2.0.0 traía dependencias con vulnerabilidades conocidas, que heredaba quien instalaba Api.
- Alta: Microsoft.Data.SqlClient 5.0.1 (GHSA-98g6-xh36-x2p7) y Azure.Identity 1.6.0 (GHSA-5mfx-4wcx-rv27). Moderada: Azure.Identity (GHSA-wvxc-855f-jvrv, GHSA-m5vv-6r4h-3vj9), System.IdentityModel.Tokens.Jwt y Microsoft.IdentityModel.JsonWebTokens 6.21.0 (GHSA-59j7-ghrg-fj52), MailKit 2.6.0 (GHSA-9j88-vvj5-vhgr) y MimeKit 2.6.0 (GHSA-g7hc-96xr-gvvx).
- Pasa a Kitpymes.Core.Logger, Kitpymes.Core.Logger.Abstractions y Kitpymes.Core.Logger.Serilog 2.1.0, que las corrige.
- Sin cambios en la API pública ni en el código de Api. El log por email de Logger cambia de comportamiento en la 2.1.0 (ver sus release notes): quien instala Api recibe Serilog 4.x y MailKit 4.x como dependencias transitivas (NU1605 si fijaba Serilog 3.x o MailKit 2.x) y los lotes que fallan se reintentan de los lotes que fallan.

# v.2.0.0
Versión mayor: rompe a quien venga de la 1.0.7 (la última publicada en NuGet, .NET 5). Abajo, qué cambia y cómo migrar.

- Requiere .NET 10 o superior.
- Usa las librerías Kitpymes ya migradas desde NuGet (Shared 2.0.1, Results 1.0.1, Entities 2.0.0, Logger 2.0.0); quien la use debe migrar también esas (ver sus release notes).
- El código pasa a github.com/kitpymes/kitpymes-core-api y el paquete se publica desde GitHub Actions.

## Cambios incompatibles y cómo migrar desde 1.0.7

1. Espacios de nombres: antes todo estaba en Kitpymes.Core.Api. Ahora hay espacios por función: ApiSession, Session.Middleware, Spa (y Spa.Settings.Angular), Swagger (Extensions, Filters, Settings) y Versioning (Settings).

2. Sesión de la aplicación
   - AppSession -> ApiSession; DependencyInjectionSession -> ApiSessionServiceCollectionExtensions y ApiSessionApplicationBuilderExtensions.

3. Versionado
   - ApiVersioning* -> Versioning*: VersioningOptions, VersioningSettings, VersioningStatus, VersioningServiceCollectionExtensions y VersioningApplicationBuilderExtensions.

4. Clases eliminadas
   - InitHost (Build, Custom y RunAsync).
   - AspNetResult.
   - SecuritySettings -> SwaggerSecuritySettings (configuración de seguridad de Swagger).
